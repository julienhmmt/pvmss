## Findings considered and rejected (do not re-audit)

- **LRU cache `Lock`→`RLock`**: false positive — `Get()` mutates LRU recency
  (`MoveToFront`) and evicts expired entries, so a write lock is correct.
  `backend/proxmox/cache.go:37`.
- **Missing DB indexes on `enabled_*`/`node_limits`**: those tables use
  `PRIMARY KEY` on the lookup column (implicit index) and are tiny config
  lists; indexing a boolean `enabled` flag is premature optimization.
- **Two markdown libs (gomarkdown backend + marked frontend)**: normal
  full-stack split (server-side vs client-side rendering), not duplication.
- **Hardcoded "secrets" in `.github/workflows/go.yml`**: these are non-secret
  test placeholders (`changeMe...`, `tokenName@changeMe!`) for
  `PVMSS_OFFLINE=true` mode, not leaked credentials.
- **Integer-parse / JSON-marshal ignored errors (admin_db.go, settings.go)**:
  defaults are applied / failure is near-impossible for the structs involved;
  low-value defensive cleanup, not worth a plan.
- **Context-cancel redundancy (vm_create.go:453)**: not a bug, just redundant
  code; no functional impact.
- **`PROXMOX_VERIFY_SSL`, `SignedString` error, pool/tag regex, SFTP filename
  boundary**: these are already tracked as OPEN findings S1/S2/S3/S6/S10 in
  `docs/plans/2026-05-22-backend-security-hardening.md`. Plan 001 covers
  Phase A (S1/S2/S3); the rest are that plan's Phase B/C — execute that
  existing plan for them rather than re-planning here.
