# Workflows

What a user actually does in PVMSS, end to end. Companion to `PRODUCT.md`
(who and why) and `DESIGN.md` (how it looks). This file is the _what_.

Every workflow below follows the same template. **Use it as the model when
adding a new one** - a workflow that cannot fill in all seven fields is not
specified yet.

```markdown
### <Name>

|                 |                                                      |
| --------------- | ---------------------------------------------------- |
| **Audience**    | end user \| admin                                    |
| **Entry**       | where the user comes from (nav item, CTA, deep link) |
| **Route**       | SPA route(s)                                         |
| **API**         | endpoints hit, in call order                         |
| **Steps**       | the happy path, numbered                             |
| **States**      | loading / empty / error / partial                    |
| **Safety nets** | confirmations, rate limits, policy gates, undo       |
```

Rules for the fields:

- **API** lists real registered routes only - check `server/internal/httpapi/router.go`
  and `router_admin.go` before writing a line here.
- **States** must name the concrete component or behaviour (a skeleton, an
  empty state, a toast), not "handles errors".
- **Safety nets** is never empty for a destructive or outward-facing action.
  If it is, the workflow has a hole (design principle 4 in `PRODUCT.md`).

## 1. Authentication

### First-run setup

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Entry**       | any page while `GET /api/v1/setup` reports `required` - the layout guard redirects to `/setup`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Route**       | `/setup`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **API**         | `GET /api/v1/setup` → `POST /api/v1/setup/admin` (when `needsAdmin`) → `POST /api/v1/auth/admin-login` → `POST /api/v1/admin/clusters/probe` → `POST /api/v1/admin/clusters`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Steps**       | 1. Read the setup status: `needsAdmin` (no bootstrap hash and no local account) and `needsCluster` (no active cluster). 2. Create the first local administrator, or sign in instead when only a cluster is missing (empty username means the bootstrap `admin`). 3. Enter the Proxmox API URL, token id and secret, and test the connection - the probe reports the discovered cluster name, version, node and VM counts. 4. Pick the cluster id (pre-filled from the discovered name, `[a-z0-9-]` only; it can be renamed later from the cluster edit form) and the display label. 5. Register the cluster; the status flips to configured, the guard lets the app through and the full router replaces the setup one. |
| **States**      | Loading while the status is undecided (a failed fetch never strands the app); inline translated errors per step (`invalid_username`, `weak_password`, `username_taken`, `setup_complete`, `invalid_credentials`, `invalid_cluster_name`, `duplicate_cluster`); a failed probe shows the connection message while still allowing the cluster to be saved.                                                                                                                                                                                                                                                                                                                                                                |
| **Safety nets** | `setup/admin` is open only while `needsAdmin` holds and answers `setup_complete` afterwards; it shares the per-IP sign-in rate limit (10/min); the status endpoint is bounded separately (120/min); the probe is session-admin only; the cluster id is validated on both ends (`^[a-z0-9-]+$`); the setup-created account is owner only when no `ADMIN_PASSWORD_HASH` exists (`created_by = 'setup'`); every mutation is audited (`setup.admin.create`, `admin.clusters.create`).                                                                                                                                                                                                                                       |

### Sign in

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Entry**       | `/login`, or any guarded page via `AuthRequired`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Route**       | `/login`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **API**         | `GET /api/v1/auth/clusters` → `POST /api/v1/auth/login` → `GET /api/v1/auth/me`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Steps**       | 1. Pick a cluster from the pre-login list. 2. Type a Proxmox username and pick the `pve` or `pam` realm - a typed `user@realm` wins over the picker. 3. Submit Proxmox credentials. 4. Session cookie is set; redirect to the requested page (`/login?next=`, set by `AuthRequired` and the admin guard; only an in-app path is honoured, otherwise the role home). A signed-in user opening `/login` is sent on the same way. A session that expires mid-use (any API 401 while signed in) shows one toast and sends the user to `/login?next=<current page>`.                                                                                          |
| **States**      | Empty cluster list when no cluster is configured; inline credential error (focus moves to the first empty field, or to the error, which the fields reference with `aria-describedby`); a rejected realm answers `realm_unsupported`; Proxmox sign-in is disabled when every configured cluster is unreachable, while local admin sign-in remains available                                                                                                                                                                                                                                                                                               |
| **Safety nets** | Per-IP rate limits: 10 requests / minute shared by login, admin-login and first-run setup (`authRateLimitMaxRequests`, `router.go:20`); the cluster list has its own bucket of 120 requests / minute (`clusterListRateLimitMaxRequests`, `router.go:24`), so page loads cannot lock sign-in out, yet it is bounded because it is unauthenticated and discloses cluster names; the backend rejects `POST /api/v1/auth/login` with `cluster_unavailable` when the selected cluster is down, so the restriction cannot be bypassed by calling the API directly; only `pve` and `pam` are accepted as password realms (OIDC goes through "Sign in with SSO") |

### Sign in with SSO

|                 |                                                                                                                                                                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user or Proxmox administrator whose cluster has an OIDC realm                                                                                                                                                                  |
| **Entry**       | "Continue with SSO" on `/login` (shown only when the selected cluster has an SSO realm and is reachable)                                                                                                                           |
| **Route**       | `/login` → IdP → `/api/v1/auth/oidc/callback` → `next` or `/`                                                                                                                                                                      |
| **API**         | `GET /api/v1/auth/clusters` (`oidcRealm`) → `GET /api/v1/auth/oidc/start?cluster=&next=` → `GET /api/v1/auth/oidc/callback?code=&state=`                                                                                           |
| **Steps**       | 1. Pick the cluster. 2. Click "Continue with SSO". 3. Sign in at the IdP. 4. Proxmox exchanges the code; PVMSS opens a session (`provider=oidc`), creating the user's pool on a first login, and sends the user to `next`. Details: `docs/oidc.md`.                            |
| **States**      | Failures return to `/login?oidc=error&reason=<code>` with a translated, focused error; `/profile` shows "Single sign-on" and no password form                                                                                      |
| **Safety nets** | Same per-IP login budget; signed, one-shot, 10-minute Lax handshake cookie checked against the echoed `state`; `next` limited to in-app paths; failed callbacks hit the login failure limiter, IdP cancels do not; a first-login pool is only granted when that login created it; a failed pool lookup refuses the login; logout is local |

### Sign in as admin

|                 |                                                                                                                                                                                                                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                  |
| **Entry**       | `/login`, separate path from the Proxmox credential form                                                                                                                                                                                                                                                                               |
| **Route**       | `/login`                                                                                                                                                                                                                                                                                                                               |
| **API**         | `POST /api/v1/auth/admin-login`                                                                                                                                                                                                                                                                                                        |
| **Steps**       | 1. Switch to Local administrator. 2. Optionally type the local account name (empty means the bootstrap `admin`). 3. Submit the password. 4. Session cookie is set with an admin identity.                                                                                                                                              |
| **States**      | Bootstrap form works whenever `ADMIN_PASSWORD_HASH` is set; DB accounts work while enabled and unlocked. Wrong password, unknown, disabled and locked accounts all answer the same generic `invalid_credentials`.                                                                                                                      |
| **Safety nets** | bcrypt hashes only (the env hash is validated at startup, `config/load.go`); five consecutive failures lock a DB account for 15 minutes, cleared by a success, a password reset or a disable; unknown usernames still pay a dummy bcrypt comparison, so timing does not reveal which accounts exist; same per-IP rate limit as sign-in |

### Manage local administrators

|                 |                                                                                                                                                                                                                                                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Audience**    | admin (bootstrap owner only)                                                                                                                                                                                                                                                                                                   |
| **Entry**       | Admin > Settings > Accounts (tab hidden for every other identity)                                                                                                                                                                                                                                                              |
| **Route**       | `/admin/settings?tab=accounts`                                                                                                                                                                                                                                                                                                 |
| **API**         | `GET /api/v1/admin/accounts` → `POST /api/v1/admin/accounts`, `PUT /api/v1/admin/accounts/{id}/password`, `POST /api/v1/admin/accounts/{id}/toggle`, `DELETE /api/v1/admin/accounts/{id}`                                                                                                                                      |
| **Steps**       | 1. Read the table: username, status (active / disabled / locked until), last sign-in, created date, and the cap usage. 2. Create an account with a username and password. 3. Reset a password, disable or enable, or delete an account from its row; each action asks for confirmation where it has an effect beyond the form. |
| **States**      | Skeleton on first load; empty state when no account exists yet; lock state shown with its expiry; translated inline errors per mutation (`account_limit_reached`, `username_taken`, `invalid_username`, `weak_password`, `not_found`, `owner_only`); success toast.                                                            |
| **Safety nets** | Owner-only server guard (`owner_only` for every other admin); `PVMSS_MAX_LOCAL_ADMINS` caps creation; `admin` is reserved for the bootstrap account; passwords are 8+ characters and at most 72 bytes; reset, disable and delete revoke that account's sessions immediately; every mutation is audited (`admin.accounts.*`).   |

Password change on `/profile` (`ProfilePasswordSection`) goes through `POST /api/v1/auth/password`: Proxmox accounts rotate the cluster password, DB local accounts rotate the hash stored in PVMSS, and the bootstrap account is told to use `ADMIN_PASSWORD_HASH` and a restart. The setup-created account is protected from delete and disable while it is the only owner (`protected_owner`); if it loses access, setting `ADMIN_PASSWORD_HASH` and restarting transfers ownership to `admin`, which can then reset or recreate the account.

### Create a VM

PVMSS adds no SSH key or password: a template
clone keeps the sign-in built into its Proxmox template, and an ISO install
gets the account the user creates during installation (README, "VM templates
carry the sign-in").

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Entry**       | "Create a machine" on `/vms`, the `/vms` first-visit empty state, or "Review the request" on a failed machine                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Route**       | `/vms/create`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **API**         | `GET /api/v1/vm-create/catalog` + `GET /api/v1/vms?pageSize=100` (names, for the duplicate check) → `POST /api/v1/vms` → `GET /api/v1/tasks/{upid}` (polled)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Steps**       | The mode chooser opens first. **Simple** is a single page with a sticky summary rail (`SimpleWizard.svelte`): 01 choose the starting point (radio cards: install from scratch, ready-made system = approved template), 02 give it room (profile radio cards; each card shows the admin's description under the spec when one is set), 03 make it yours (name, tags), startup options; the rail repeats every choice live, shows the allowance after creation and holds "Create this machine". **Detailed** keeps the stepper: 1. Base (name, profile, cluster, node). 2. Disk. 3. Hardware. 4. Network. 5. Review - the only place raw JSON is shown, and only on request. 6. Submit; the response is a Proxmox UPID. 7. The task tray polls until done, then refreshes the VM list. Detailed mode may pick a Proxmox template as the source instead of an ISO: the node is derived from the template (the selector hides), the disk minimum rises to the template's disk, and the wizard says when the target storage forces a full copy instead of a linked clone.                                                             |
| **States**      | Blocked states replace the form: "We can't load the available choices" (catalog error, Try again), "You've reached your machine allowance" (quota used up), "Your catalog isn't ready yet" (no profile or template approved); the wizard shows skeletons while the catalog loads. A single possible starting point is named, not offered as a choice. No size is preselected; a refused submit leaves a line under the disabled button ("Choose a size to continue." or "Fix the highlighted fields to continue."). Inline field errors and a disabled submit while the form is invalid; the detailed stepper only ticks a step once its values are valid and refuses to jump forward over an incomplete one (the click lands on that step with its errors shown), and Review keeps Create disabled while naming the step still to complete; entered values survive a mode switch and recoverable errors (a reload starts over). Task tray shows in-flight work so the user can navigate away. Template source: the template option only appears when at least one template is approved; an empty catalog legitimately hides it. |
| **Safety nets** | A name already used by one of the user's machines is refused before submit; when that machine is `partial` the message says "Do not create a duplicate: open it instead" (the server's `name_taken` stays the real guard). Every choice comes from the admin-approved catalog - nodes, storages, bridges, ISOs, profiles, VM templates, tags. Quotas and gabarit limits are checked server-side (`policy/`), not in the wizard. A template clone stays on the template's node (the wizard hides the node selector), the disk size can never drop below the template's disk, and a stale or deleted template fails fast before a VMID is spent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Entry**       | View details / the name link on a `/vms` row, an Activity row, the sidebar machines drawer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Route**       | `/vms/[cluster]/[vmid]`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **API**         | `GET /api/v1/vms/{cluster}/{vmid}` → `GET /api/v1/vms/{cluster}/{vmid}/cloudinit` (SSH user, when connectable) → `POST .../actions` + `GET .../status` (header power action) plus the per-tab endpoints below                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Steps**       | Connection-first (`VmDetail.svelte`, DESIGN.md §6.3). 1. The header shows the OS mark, name (click to rename), identity line (size, VM id, cluster), status pill, "Open the console" (disabled with a hint unless running), the state-appropriate power action (Start machine, or Shut down with an inline confirmation) and one overflow menu with the other applicable power actions, Duplicate, Delete and, for admins, the SeaBIOS retrofit. 2. Overview (default tab): the SSH command built from the address the guest agent reports, with Copy; a stopped machine gets a compact card with Start; a Details rail (size, disk, VM id, cluster, node/pool for admins, lease + extend) and the editable description; usage charts. 3. Disks, Network, Hardware, Snapshots: one flat tab per panel. 4. Activity: the per-machine audit trail, paged newest first; rows carry checkboxes with a per-page select-all, and Export CSV downloads either the checked rows or, when nothing is checked, every entry inside the chosen range (24h / 7d / 30d / All - fetched page by page client-side, stopping once an entry is older than the range).                                                                        |
| **States**      | Detail skeleton on first load. Banners above the tabs, in priority order: shutdown confirmation; provisioning (4-step panel, "Back to my workspace"); failed ("Review the request") / partial ("Do not create a duplicate", "Get help from your administrator", technical details); starting / stopping. Overview tab (`connectState()` in `connection.ts`): "SSH isn't available right now" with an inline Start button when not running; "Installation in progress" while an ISO is mounted and the machine boots from it or reports no address yet; new machines boot disk-first, so a reboot after the install lands on the disk even with the ISO still mounted (console as primary action, "Eject the ISO" calls `PATCH .../cdrom` with `disconnect`); otherwise "Connect with SSH" only with a reported address, else "The address isn't available yet" with a hint per guest-agent state (disabled, unreachable: install `qemu-guest-agent`, answering without an address: network not configured yet). PVMSS never probes port 22 (the address is guest-reported, so a probe would be an SSRF vector). The console opens in a new tab and is offered only while running. The History charts collapse to a single muted note while the machine is not running. The Snapshots and Activity panels mount lazily. |

|                 |                                                                                                                                                                                                                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user                                                                                                                                                                                                                                                                                                |
| **Entry**       | "Duplicate" item in the VM detail header overflow menu (`VmActionBar.svelte`)                                                                                                                                                                                                                                       |
| **Route**       | `/vms/[cluster]/[vmid]` (dialog on the same page), then `/vms` once the task finishes                                                                                                                                                                                                                   |
| **API**         | `POST /api/v1/vms/{cluster}/{vmid}/clone` `{name}` (202 with UPID), then `GET /api/v1/tasks/{upid}` polled by the task tray                                                                                                                                                                             |

| Field           | Content                                                                                                                                                                                                                                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user (owner), admin                                                                                                                                                                                                                                                                                     |
| **Entry**       | The "Lease" row in the Details rail of the Overview tab (`/vms/[cluster]/[vmid]`), shown only for a leased VM                                                                                                                                                                                                      |
| **Route**       | `/vms/[cluster]/[vmid]`                                                                                                                                                                                                                                                                                     |

| **States**      | The date turns to the warning colour inside 7 days. A refused extension shows an inline alert and keeps the old date. ### Schedule automatic snapshots

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | end user                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Entry**       | Snapshots tab of a machine (schedule form above the list)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Route**       | `/vms/[cluster]/[vmid]?tab=snapshots`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **API**         | `GET .../snapshots` (returns the schedule), `PUT .../snapshot-schedule`, `DELETE .../snapshot-schedule`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Entry**       | "Quota requests waiting" row in the dashboard needs-attention block, or the "Quota requests" entry of the policy group in the admin sidebar (`/admin/quota-requests`)                                                                                                                                                                                                                                                                                                                |
| **Route**       | `/admin/quota-requests`                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **API**         | `GET /api/v1/admin/quota-requests?status=pending` → `POST /api/v1/admin/quota-requests/{id}/approve` (optional `quota`) or `POST /api/v1/admin/quota-requests/{id}/deny`                                                                                                                                                                                                                                                                                                             |
| **Steps**       | 1. Open the pending list: one row per request with requester, pool, current and requested allowance, and reason. 2. Optionally type a different allowance to grant. 3. Approve: a quota override for the requester's pool is written and the request is marked approved. Or deny: the allowance is left unchanged.                                                                                                                                                                   |
| **States**      | Empty: "No pending requests". A load error line. A decision another admin already made returns 409 and the list reloads.                                                                                                                                                                                                                                                                                                                                                             |
| **Safety nets** | Admin-only routes behind the admin guard and CSRF. Approval writes a per-pool override through the same validation as `/admin/policy` (400 `invalid_policy`), committed atomically with the decision - the cluster-wide cap is never touched, so other pools are unaffected. Each decision writes an audit row: `quota.request_approved` (pool allowance old and new, requested number) or `quota.request_denied`. A pending request for a pool that is no longer managed is denied. |

### Set a per-pool quota override

| Field           | Content                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                                              |
| **Entry**       | Administration -> Infrastructure -> PVMSS users -> pool row (`/admin/pools/[name]?cluster=`), allowance section; overrides listed on `/admin/policy`                                                                                                                                                                                                               |
| **Route**       | `/admin/pools/[name]?cluster=`                                                                                                                                                                                                                                                                                                                                     |
| **API**         | `GET /api/v1/admin/quota-overrides` (list) → `PUT /api/v1/admin/quota-overrides/{cluster}/{pool}` (set) or `DELETE /api/v1/admin/quota-overrides/{cluster}/{pool}` (remove)                                                                                                                                                                                        |
| **Steps**       | 1. Open the pool's details page: the allowance meter shows the effective allowance and whether it comes from the cluster policy or an override. 2. Set a different allowance: the pool gets its own cap, independent of the cluster policy. 3. Remove the override: the pool falls back to the cluster quota.                                                      |
| **States**      | "Cluster default" when no override exists; the override value and who set it otherwise; the policy page lists every override on the cluster.                                                                                                                                                                                                                       |
| **Safety nets** | Admin-only routes behind the admin guard and CSRF; the value is validated like the policy allowance (400 `invalid_policy`). An override never changes the cluster policy - it scopes to one pool. Deleting a managed pool removes its override; the write is compare-and-swapped so a concurrent override update is retried rather than lost. Changes are audited. |

### Set the VMID range

| Field           | Content                                                                                                                                                                                                                                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                           |
| **Entry**       | Administration -> Policy (`/admin/policy`), "VM ID range" fields in the gabarit section                                                                                                                                                                                                                         |
| **Route**       | `/admin/policy`                                                                                                                                                                                                                                                                                                 |
| **API**         | `GET /api/v1/admin/policy` → `PUT /api/v1/admin/policy` (gabarit `vmidMin`, `vmidMax`) → `POST /api/v1/vms` (409 `vmid_range_exhausted` when the range is full)                                                                                                                                                 |
| **Steps**       | 1. Pick the cluster on the Policy page. 2. Enter the first and last ID. Both 0 means Proxmox's next free ID; otherwise use 100 <= first <= last <= 999999999 (for example 9000 and 9999). 3. Save. 4. New VMs take the lowest ID in the range that no VM or container on the cluster uses, whoever created it.  |
| **States**      | Inline range error under the first ID field when the range is invalid (same rule as the server); a hint explains the 0/0 default; a server error is shown on the field it names.                                                                                                                                |
| **Safety nets** | The range is validated on both sides (400 `invalid_policy` from the server). Existing VMs are never renumbered; the range only chooses ids for new VMs. Each changed bound writes an audit row (`gabarit.vmidMin`, `gabarit.vmidMax`). A full range refuses the create with 409 before the Proxmox create call. |

### Set the lease length

| Field           | Content                                                                                                                                                                                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                 |
| **Entry**       | Administration -> Policy (`/admin/policy`), "Leases" section                                                                                                                                                                                                                                                                          |
| **Route**       | `/admin/policy`                                                                                                                                                                                                                                                                                                                       |
| **API**         | `GET /api/v1/admin/policy` → `PUT /api/v1/admin/policy` (gabarit `leaseDays`)                                                                                                                                                                                                                                                         |
| **Steps**       | 1. Pick the cluster. 2. Enter the lease length in days (0 turns leases off, max 3650). 3. Save. 4. VMs created from now on get an expiry of that many days. Owners can extend up to that length at a time.                                                                                                                            |
| **States**      | A server error is shown on the field it names. Changing the value marks the form dirty.                                                                                                                                                                                                                                               |
| **Safety nets** | Validated on the server (400 `invalid_policy`). Each change writes an audit row (`gabarit.leaseDays`). Only VMs created while the length is above 0 get a lease: VMs created earlier have no lease and never expire. A lease is never added to an existing VM (no endpoint does it). The sweeper runs once at startup and then daily. |

### Adopt leftovers from a previous install

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audience**    | admin                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Entry**       | sidebar Administration > System > Recovery - used after a fresh PVMSS install (new database) points at a cluster an older instance already managed                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Route**       | `/admin/recovery`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **API**         | `GET /api/v1/admin/recovery?cluster=` → `POST /api/v1/admin/recovery` (adopt) → `POST /api/v1/admin/recovery/scan` (forced rescan)                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Steps**       | 1. Pick the cluster. 2. Read the report: orphan `pvmss-*` pools with their member VMs (name, node, status, tags), stray `pvmss`-tagged VMs outside managed pools, and catalog tags lost with the old database (each with a suggested color and its VM count). 3. Uncheck the pools and tags to leave as-is - everything is pre-selected. 4. "Adopt selected" re-marks pools managed and recreates the checked tags with the suggested color; the page reloads the report. 5. "Rescan" forces a fresh Proxmox read when the admin knows leftovers changed. |
| **States**      | Table skeleton while scanning; `cluster_not_found`, `cluster_unreachable`, `inventory_not_ready` and generic errors in an Alert; `nothingSelected` when adopt is clicked with an empty selection; empty state once nothing is adoptable; success announced in an aria-live region (`{pools} pools, {tags} tags`)                                                                                                                                                                                                                                          |
| **Safety nets** | Read endpoints are cached per cluster (5-minute cooldown) and pinned forever once nothing is adoptable - page visits stop hitting Proxmox; the forced rescan is a POST so it gets CSRF and the mutation rate limit; adoption writes PVMSS-local rows only (`managed_pools`, `catalog_tags`) and never touches VM tags on the cluster, so declined tags stay exactly as they are; unknown names are ignored so a stale report cannot corrupt another cluster; the adopt is audited (`admin.recovery.adopt`)                                                |

## Cross-cutting

These apply to every workflow above; a new workflow inherits them.

| Concern           | Where                                                                                                          |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| i18n              | Paraglide, EN + FR + DE + IT, `m['...']()` message keys - no bare user-facing strings                          |
| Background work   | Task tray polls `GET /api/v1/tasks/{upid}` and refreshes the affected list on completion                       |
| Loading           | `TableSkeleton` and per-feature skeletons, never a blank page                                                  |
| Quotas            | `Meter` / `quota-meter` components fed by `policy/`                                                            |
| Accessibility     | `role="tabpanel"` panels, focus trap in dialogs, skip-to-content link, visible focus rings                     |
| Security headers  | `withSecurityHeaders` wraps the whole mux - CSP, HSTS, frame and content-type options, cache-control on `/api` |
| Unknown API paths | Return a JSON `{"detail": "unknown API path"}` 404, never the SPA shell                                        |
